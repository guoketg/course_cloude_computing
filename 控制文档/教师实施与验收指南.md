# 教师实施与验收指南

本指南面向授课老师，用来把课程材料变成可实际开设的 8 次实验和两周个人项目。时间、先修、能力目标与总体评价见 [课程总体设计方案](课程总体设计方案.md)，每章操作与评分以对应实验目录为准。

验收记录用 `PASS`、`FAIL` 和“未执行”如实区分。基础路径和默认模型路径是两条完整教学路径：学生不选择模型路径时，不写 `SKIP`，也不承担分析教师模型输出的替代义务。脚本导入成功、阅读文档和观看演示都不能冒充本人实际运行。

## 1. 开课前的最低准备

### 1.1 教学约定

- 学生材料按实验任务、操作步骤、结果和验收要求组织，不给每一步规定完成时限，也不划分课内与课后任务。
- 学生为计算机科班，但没有大数据开发经验且编码能力偏弱；开课前安排少量 Python/SQL 复习。无 Docker/Linux/GPU 前提，参考平台为 Windows 11 64 位、Python 3.12、CPU、16 GB 内存。
- 统一使用虚构校园 AI 推理事件与自制政策材料；不接入真实个人日志。
- 每章先保留预测，再运行；至少一项本人核心规则/代码改动，必须有结果变化和 diff。
- 05/06 保留真实 CPU embedding 与本地小 LLM 的完整实践，同时提供工作量相当的词法检索与确定式摘录路径；两条路径均可完成必达目标和获得满分。
- “在系统中运行模型”和“用 AI 助手学习”是两件事。二者均由学生自愿选择；使用助手者简短披露并自行核实，未使用者不交空白记录。

### 1.2 课前问卷与预检

在第 1 次课前一周收集 Windows 版本、CPU、内存、可用磁盘、Python 是否可运行、学校网络是否可访问依赖站点。不得要求学生公开设备序列号、账户密码或 API 密钥。

本轮按用户明确指定采用 **FF11 实际环境**验证基础路径及固定 BGE + Qwen3.5 0.8B Q8_0 默认组合，记录实际 RAM、CPU、操作系统、运行设备和资源占用；未执行项仍标“未执行”。不再将缺少物理 16 GB 机器作为本轮发布阻塞。学生 16 GB 是参考目标与尚未实测的兼容边界，禁止把 FF11 结果写成 16 GB 认证；保留历史验证记录与旧审计结论，不覆盖或追改。学生材料只保留笔记本上的默认模型对照，不要求额外 GPU 或大内存设备。若学生机不适合模型路径，直接选择基础路径，不应因无法购买硬件失去分数。

在 FF11 的课程目录记录实际环境，以下命令只读取系统信息；不预填机器配置：

```powershell
Get-CimInstance Win32_ComputerSystem | Select-Object Model, @{Name='RAM_GiB';Expression={[math]::Round($_.TotalPhysicalMemory / 1GB, 2)}}
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors
Get-CimInstance Win32_OperatingSystem | Select-Object Caption, Version, TotalVisibleMemorySize, FreePhysicalMemory
Get-Process -Name python,ollama,ollama_llama_server -ErrorAction SilentlyContinue | Select-Object Id, ProcessName, CPU, WorkingSet64, PeakWorkingSet64
```

记录运行前空闲内存、运行中系统可用内存与相关进程占用、冷/热耗时、采样间隔及是否出现换页或内存错误。进程名以实际环境为准；上述进程列表只是一次快照，不能当作全程峰值。验证者需用实际监测结果填写峰值及测量口径；缺少监测数据就写未测，不用模型磁盘大小推算 RAM。默认 CPU 设置和实际 GPU 使用情况也须分别记录。

### 1.3 依赖与模型冻结

使用课程包的 `requirements.lock.txt` 安装数据/词法基础；模型环境按 `requirements-models.lock.txt` 和实验 5/6 手册配置。锁文件固定版本但未记录 wheel 哈希，不能称为制品哈希锁定。直接依赖清单 `requirements.txt` 用于阅读，不应临时全部升级。安装后记录 `pip freeze`、课程代码版本、数据种子和散列。

Ollama 运行时与模型另行记录：运行时版本、模型名、模型包标识、实际下载大小与获取日期。语义模型记录名称及 revision。实验 05 固定 BGE；实验 06 固定 Qwen3.5 0.8B Q8_0 课程制品并导入为 `bdp-qwen35:0.8b-q8_0`。具体 revision 和 SHA-256 由准备脚本与 manifest 统一核对，不以“最新版”代替。

对模型缓存做断网或离线模式验证：能够从已有本地文件完成模型加载、文本编码与生成，才叫“可离线运行”。仅看到下载目录存在不够；有些加载代码仍会请求模型仓库元数据。若该版本仍需联网，必须提前修正加载路径或明确网络前提，不能在手册里写成离线。

## 2. 教师基线验收

以下命令仅供教师在自己的课程验收目录执行。示例安装位置为 `C:\BDP`，按实际位置修改。不要用学生正在提交的目录做重置或生成测试。

### 2.1 安装与检查

```powershell
Set-Location 'C:\BDP'
py -3.12 -m venv .venv
$coursePyPI = 'https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple'
.\.venv\Scripts\python.exe -m pip install --index-url $coursePyPI -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip check
New-Item -ItemType Directory -Path '.\outputs' -Force | Out-Null
$teacherTestRoot = Join-Path (Get-Location) ('outputs\pytest-teacher-' + [guid]::NewGuid().ToString('N'))
.\.venv\Scripts\python.exe -m pytest tests -q --basetemp $teacherTestRoot
```

虚拟环境隔离课程依赖；`pip check` 检查依赖约束；测试验证代码中的关键不变量。测试通过并不意味着 HTTP 服务、模型、整套手册都已实测，需要继续下面各节。

如 PowerShell 允许本地脚本，运行：

```powershell
.\scripts\verify-environment.ps1
.\scripts\run-baseline.ps1
```

若学校执行策略禁止脚本，按脚本内的解释器命令逐条执行即可，不要求学生永久放宽全局执行策略。`verify-environment.ps1` 检查基础模块，不涵盖真实模型；`run-baseline.ps1` 是教师用的 01—06 词法/摘录基线 smoke，学生仍应逐章学习，不能用一键执行代替预测和改动。

基线脚本在 `outputs/smoke-...` 中创建独立数据根，避免覆盖课程主数据。记下脚本最后输出的真实路径，后续 HTTP 验收必须指向同一个根。不要猜测最近一个文件夹就一定是这次结果。

### 2.2 基线确定值与检查口径

| 项目 | 应检查什么 | 不应强求什么 |
|---|---|---|
| 默认数据 | 20,000 条合法唯一 + 100 重复 + 2 非法，共 20,102 行 | 不把手工修改后的数据还套用默认数字 |
| S3 仿真 | HTTP 上传/下载真正发生，内容散列一致 | 公有云耐久性、跨区域一致性 |
| 清洗 | 仅合法唯一数据进入 silver；质量报告解释剔除项 | 只看最后显示“成功” |
| 列式/批处理 | Parquet 可读，DuckDB 与 Dask 关键聚合一致 | Dask 必须比 DuckDB 快 |
| 进程 | 使用真正 worker 进程并保留配置/进程证据 | 单机等于跨机容灾 |
| 微批恢复 | 首次处理、重放、中断、恢复各有状态；检查点与事务一致 | 检查点本身提供所有外部输出的 exactly-once |
| 词法/摘录 | 模式如实写入结果；来源和拒答可查 | 把它们当成 embedding/LLM |
| 版本 | 清单与实际文件对应；旧索引/篡改被发现 | 只检查响应里存在 `version` 字段 |

数据行数与逻辑结果可严格核对；带时间戳的产物散列、性能时间和生成文本可能变化，分别记录可重现范围。

### 2.3 HTTP 服务与发布验收

打开两个 PowerShell 窗口，二者进入同一课程目录，并将 `BDP_ROOT` 设置为 **上一步实际输出的 smoke 根目录**。下方路径只是示意，必须替换 `smoke-实际编号`。

窗口 A：

```powershell
Set-Location 'C:\BDP'
$env:BDP_ROOT = 'C:\BDP\outputs\smoke-实际编号'
$env:PYTHONUTF8 = '1'
$env:BDP_EXPERIMENT_ID = '07'
.\.venv\Scripts\python.exe -m uvicorn coursekit.service:app --host 127.0.0.1 --port 8000
```

窗口 B：

```powershell
Set-Location 'C:\BDP'
$env:BDP_ROOT = 'C:\BDP\outputs\smoke-实际编号'
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/health'
.\.venv\Scripts\python.exe -m coursekit lab07 --requests 20
.\.venv\Scripts\python.exe -m coursekit lab08
```

窗口 A 用 `Ctrl+C` 正常停止。验收结束后，在两个窗口中分别移除临时环境变量，避免后续误用：

```powershell
Remove-Item Env:BDP_ROOT -ErrorAction SilentlyContinue
```

不同数据根会使“我的文件已更新但服务仍旧”成为真实问题；教师应先核对环境变量与工作目录，再判断代码错误。发布检查还应配合人工检查源码，确认不是硬编码 PASS。权限、注入和数据篡改测试的覆盖范围应如实说明；一组测试不能证明全面安全。

当前发布门禁读取冻结的 `evaluation_test_extractive.json` 和真实 HTTP 负载证据，并核对身份与当前代码、配置、题集和索引。先完成全部 dev 练习与故障修复，再执行 `coursekit freeze --generator extractive`，然后 `coursekit lab06 --split test --generator extractive`；代码或配置改变后重新 freeze、重评并重新启动服务/测量 HTTP。已看过 test 时在报告标记“test 已见”，记录查看时间、变更原因和前后结果；重测属于回归，不能仍称未见测试集。评价必须有可回答正例的有效接受，全部拒答不能通过发布。服务默认采用可复算摘录路径。门禁通过不等于真实 LLM 回答已经满足引用/忠实度要求；模型对照应独立分析。若个人项目把 LLM 作为实际发布生成器，应增加与该生成器一致的验收，不能借用摘录结果替其背书。

## 3. 可选模型路径的准备与验收

### 3.1 课前材料

准备四类材料：锁定的 Python wheelhouse、BGE 文件、Ollama 官方安装程序的校验副本、Qwen3.5 GGUF。依赖和模型下载均放在课前；课堂只检查文件校验、模型列表和一次短请求。

联网准备使用清华 PyPI 一次性源，不改全局配置。随后生成和核对 wheelhouse manifest：

```powershell
$coursePyPI = 'https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple'
.\.venv\Scripts\python.exe -m pip download --index-url $coursePyPI -r .\requirements-models.lock.txt -d .\wheelhouse
.\.venv\Scripts\python.exe .\scripts\artifact_manifest.py create .\wheelhouse .\wheelhouse-manifest.json
.\.venv\Scripts\python.exe .\scripts\artifact_manifest.py verify .\wheelhouse .\wheelhouse-manifest.json
.\.venv\Scripts\python.exe -m pip install --no-index --find-links .\wheelhouse -r .\requirements-models.lock.txt
```

BGE 继续使用现有固定模型 revision；准备脚本从 ModelScope 固定 source revision 逐文件下载并核对 SHA-256。离线使用前核对 manifest，并显式指向本地目录：

```powershell
.\.venv\Scripts\python.exe .\scripts\prepare_embedding.py
.\.venv\Scripts\python.exe .\scripts\prepare_embedding.py --verify-only
$env:BDP_EMBED_MODEL = (Resolve-Path .\models\bge-small-zh-v1.5).Path
$env:HF_HUB_OFFLINE = '1'
```

`HF_ENDPOINT` 只影响 Hugging Face Hub，不是 Ollama registry 镜像设置；本课默认准备不依赖它。默认 GGUF 从 ModelScope 的固定 `ggml-org/Qwen3.5-0.8B-GGUF` revision 获取；该文件是社区转换，准备脚本核对完整字节数、SHA-256 和 GGUF 文件头后才允许导入本地 Ollama tag：

```powershell
.\.venv\Scripts\python.exe .\scripts\prepare_generation.py prepare
.\.venv\Scripts\python.exe .\scripts\prepare_generation.py verify
.\.venv\Scripts\python.exe .\scripts\prepare_generation.py import-ollama
$env:BDP_OLLAMA_MODEL = 'bdp-qwen35:0.8b-q8_0'
ollama list
```

学生可在自己的笔记本上准备与上述路径完全相同、校验值一致的离线缓存：BGE 用 `prepare_embedding.py --local-source <目录>`，GGUF 用 `prepare_generation.py prepare --local-file <路径>` 纳入同一校验流程。社区转换 GGUF、自定义本地 tag 和 Ollama 官方 registry tag 不能共用身份或 digest。若更换制品，应同步更新 manifest、配置、证据和受影响的验收。

新开模型或语义服务终端时，重新设置上述本地 `BDP_EMBED_MODEL`、`HF_HUB_OFFLINE=1`、完整 Ollama tag；综合项目服务另设 `BDP_EXPERIMENT_ID=09`。另一终端设置不作用于已启动进程，重启后须真实调用 `/ask`；只看 `/health` 不证明模型成功加载。

### 3.2 两种验收档案

本轮两档均在 FF11 实际环境执行，分别记录环境和资源。基础档案先在无模型依赖的独立环境实际完成 01—04、05 词法、06 dev→freeze→test 摘录、07 和 08；模型档案另在固定 BGE + Qwen3.5 0.8B Q8_0 组合上完成 05 语义索引、BGE probe、06 dev→freeze→test Ollama 生成。各档使用独立数据根，避免模型依赖或旧产物混入基础档。自动脚本不能代替手册独立练习与真实截图复核。

`scripts/capture_validation.py` **只归档已实际产生的结果，不执行上述实验**。先核对来源根目录、当前版本及必需文件，再归档；每轮使用新的目标目录，禁止覆盖旧版根目录或已有 profile 的历史证据。下面两个来源路径必须替换为本轮实际执行目录；若两档分次执行，记下同一个新归档目录值：

```powershell
$validationArchive = Join-Path (Get-Location) ('控制文档\验证证据\FF11-' + [guid]::NewGuid().ToString('N'))
$baseSourceRoot = 'C:\BDP\outputs\本轮基础档实际目录'
$defaultModelSourceRoot = 'C:\BDP\outputs\本轮模型档实际目录'
.\.venv\Scripts\python.exe .\scripts\capture_validation.py --profile base --source-root $baseSourceRoot --target-root $validationArchive
.\.venv\Scripts\python.exe .\scripts\capture_validation.py --profile default-model --source-root $defaultModelSourceRoot --model-root . --target-root $validationArchive
```

两档分别归档到新目标目录下的 `base/`、`default-model/`。缺少产物或核对失败不应填 PASS；保留真实失败和恢复记录。本轮 FF11 验收与学生 16 GB 兼容性验证分开报告，后者仍为尚未实测的边界，不作本轮阻塞。

学生按自己选择的路径运行。模型路径先串行完成 05 BGE 并释放资源，再由 06 单请求调用默认小模型；07/08 可继续用摘录服务，不要求模型常驻。调参只用 dev；所有 dev 练习与故障修复完成后才 freeze、test。冻结后改动须按第 2.3 节重新冻结和复评，不覆盖此前证据。生成文本可能变化，需保留逐题输出并人工核对原文支持。

### 3.3 教师示范与挑战边界

教师保存固定默认组合的输入、模型 manifest、硬件、命令、逐题结果、耗时和错误。示范可展示精确编号更适合词法、改写可能受益于语义、引用存在但说法无依据等现象；若实际结果没有出现某类现象，使用明确标注的人工反例，不能伪造运行输出。

Qwen3 0.6B Q4 的旧结果只保留为旧流程历史记录，不重测也不作为新默认路径证据。2B/4B/9B/27B 与 GPU 配置都是学生自愿挑战，兼容性和性能不作教师实测承诺，也不影响满分。默认使用 CPU；选择 GPU 的学生通过 `BDP_OLLAMA_NUM_GPU` 显式配置并自行记录实际设备和显存。在线付费 API 完全由学生决定，课程不要求购买或指定服务，密钥不得提交。

## 4. 八次课的课堂组织

| 实验 | 教师课前复核 | 课堂重点提问 | 易误解点与纠正 |
|---|---|---|---|
| 01 | 环境、临时 HTTP 服务、散列 | 上传成功为什么还要比较散列？对象键是否等于文件夹？ | Moto 是 API 仿真，服务停止后云侧对象不作为持久源 |
| 02 | 默认异常数、Parquet、清单 | 同一个 event_id 内容不同应怎样处置？ | 简单去重规则要声明适用条件；Parquet 不是完整湖仓系统 |
| 03 | worker 进程、结果对照、配置保存 | 加一倍 worker 为什么可能变慢？ | 更慢可以正确；比较先检查结果一致 |
| 04 | 故障位置、事务与状态、晚到 | 数据写完但检查点没写会怎样？ | 主键、检查点、输出提交不是一个概念 |
| 05 | 词法路径可复算；默认 BGE 可选路径离线可用 | 为什么模型换了要重建索引？ | 相似度不等于可信度；只做一种关键词排序即可完成必达目标 |
| 06 | 摘录路径与可选 Qwen 路径均可独立完成 | 引用存在但说法错误怎么发现？ | 引用存在性和充分忠实度分开；生成质量低不降低数据/权限要求 |
| 07 | 两终端同根、实际负载、缓存版本 | 快了一半是缓存、少算了还是测量错了？ | 统计事件耗时与 HTTP 端到端耗时分开；role 输入非认证 |
| 08 | 真实篡改/版本/权限路径、恢复 | 为什么所有 HTTP 200 仍可能不准发布？ | 发布依据质量与权限等不变量，不只进程存活 |

同学求助时，授课老师先检查输入文件与配置，再看异常；不要直接替学生完成独立环节。可提供语法提示，但让学生自己决定规则并写下理由。

## 5. 评分的一致性与真实性

### 5.1 先看证据对应关系

报告里的每个重要结论应对应源数据、命令、版本、结果字段或代码 diff。实验 01—09 执行统一的 [学号与提交验收](../docs/学号与提交验收.md)：所有评分截图（包括失败、恢复和环境）必须原生显示名册学号、本次提交编号、run_id 与真实结果，截图不能单独代替机器可读结果。仅文件名、报告首页、另贴学号图、后期叠字、UNREGISTERED 或身份/原始结果不一致，均须退回补证。前章 JSON 可引用原编号，截图必须通过本章命令或 capture 重新运行取证。学生输入被修改后，默认 20,000 等数字不再是唯一正确答案，应按学生契约计算。

模型分数、性能和延迟不要按高低排名评分。学生能证明受控比较、发现失败、解释局限，应得到相应分数。若数字非常漂亮但没有原始样本，应补查，不能因截图美观就默认真实。

### 5.2 提交清单与逐图人工验收

学生使用 `submission-manifest --lab 本章编号 --directory 提交目录 --report 包内报告相对路径`，将报告、运行 JSON/同名 HTML、截图及原始文件/对应 `*.identity.json` 整理成提交包。MD 正文须含本人学号；PDF 可由教师人工核对。无图、无本章真实 coursekit.run、HTML 与同名 JSON 渲染不一致、evidence 中 JSON 无身份也无有效旁证，都不能生成合格清单。

教师验收顺序：

1. 根据教师名册取学号，先运行 `submission-check --directory 提交目录 --student-id 名册学号`。文件检查通过但缺 review 时返回 **2：待人工复核**，不得当成通过。
2. 打开报告，并逐张打开清单中的截图，对照真实运行 JSON、HTML 与原始结果。核对原生学号、本章编号、run_id、具体结果或错误；只有固定标题而没有真实结果的画面不合格。HTTP 页的 run_id 也必须有已提交 coursekit.run 对应；跨章结果改用本章 capture 重新生成视图。
3. 在**提交包外**保存教师本人维护的 review。完整 JSON 示例见本文件末尾“提交复核操作”。顶层必须有 `reviewer`、`manifest_sha256`、`report_sha256`、`report_student_id`、`report_passed:true`、`screenshots`；每张截图一项 `file`、`sha256`、`student_id`、`experiment_id`、`run_id`、`passed:true`，不能漏图、重复或增加无关项。只有实际复核合格才填 true。`file` 为清单内相对路径；截图编号须等于本次提交编号，run_id 须对应已提交 coursekit.run。报告与清单的哈希须绑定本次实际复核文件。
4. 执行带 `--review 包外教师review.json` 的 submission-check。**失败 1，通过 0**；无 review 的 2 永远是待复核。文件改变后重建清单、重新看图和报告，不沿用旧 review。

机器只核对字段、身份、文件与运行关联，不能替教师看图，也不能用哈希声称防伪。学生包内自签 review 无效。身份与证据验收是前提，业务分仍按各章 100 分表评定；基础路径和模型路径同分。预期故障可按真实分析获得对应分，不以子程序非零退出一概判零。

本轮集中验收至少记录以下正负案例：完整且逐图复核的提交；缺截图/本章运行记录；无学号/UNREGISTERED/名册不符；错章截图或无对应 run_id；不匹配的 HTML/JSON；缺原始文件旁证；无 review；漏审图片；旧清单或报告哈希；PDF 人工复核。此处是验收要求，执行结果须另记，不能把清单本身当作 PASS。

### 5.3 独立环节抽查

每次随机抽一个微小变式，如修改 1 条重复记录、调低阈值、增加一个相关文档、把角色换为 public。先让学生预测，再运行。此环节不用 AI，可查阅自己的代码。记录理解情况，不靠 AI 风格检测器判断作者身份。

仅在学生使用 AI 助手时检查其简短披露能否说明“建议—采纳/拒绝—本人修改—验证”。没有使用 AI 的学生无需另交记录或未使用声明，仍可满分；大量调用不会增加分数。发现伪造证据时遵循学校正式流程，不在本指南自行制定处分。

### 5.4 两周项目的管理

第 2 天看一页用户问题与数据流；第 4 天看一次真实完整请求；第 7 天看两项核心改动和小数据参照；第 10 天看失败恢复；第 13 天看复建。教师每次只反馈阻塞主线的少数问题，避免把一个人两周项目膨胀成团队平台工程。

项目代码可复用课程组件，但应有两项关联独立改动。不要按新增组件数量、代码行数或模型参数量评价项目。详细 100 分表和失败上限见项目任务书。

## 6. 常见现场问题处理

| 现象 | 首先确认 | 处理方向 |
|---|---|---|
| 找不到模块 | 当前目录、`.venv` 解释器、pip 是否同环境 | 用完整解释器路径安装/运行，不要求全局安装 |
| PowerShell 脚本受限 | 学校策略、是否仅激活脚本受限 | 直接调用 `.venv\Scripts\python.exe`，不永久改全局策略 |
| 中文请求乱码 | 文件编码、请求 Content-Type、请求体字节 | 按手册显式 UTF-8；保留原始错误再复验 |
| Dask 子进程报错 | 从模块入口启动、是否有主入口保护、数据路径 | 避免在交互式片段中重复创建进程；先运行 1 worker |
| HTTP 端口占用 | 是否已启动同一服务、另一窗口是否仍运行 | 正常停止本人服务；不杀不明进程 |
| 明明更新却读到旧结果 | BDP_ROOT、当前目录、服务进程、索引清单、缓存键 | 依次核对路径和版本，不能只重启掩盖根因 |
| 模型缓存仍联网 | 是否请求仓库元数据、加载路径是否本地、revision 是否匹配 | 完成离线预检；学生可改选完整基础路径，不能把联网失败冒充离线成功 |
| 模型生成很慢 | CPU、上下文、输出上限、冷启动、并发负载 | 使用已验收小模型和短输出，分开冷/热测量 |
| 发布检查失败 | 哪项规则、实际文件是否修改、恢复是否完整 | 修复原因并重跑，不手改 release JSON 为 PASS |

## 提交复核操作

教师先按名册学号运行机器检查。下列目录与学号需要替换为实际值：

```powershell
$rosterStudentId = Read-Host '请输入教师名册中的学号'
.\.venv\Scripts\python.exe -m coursekit submission-check --directory .\提交\实验01 --student-id $rosterStudentId
```

机器核对 JSON 证据身份、实验/项目号、运行关联和提交文件一致性。文件检查通过但缺少 review 时返回码为 **2，待人工复核**，不是通过；检查失败为 **1**，全部通过为 **0**。教师必须打开清单中的每张截图，核对画面中的学号、实验/项目号、run_id、真实结果与原始 JSON/HTML；还要复核报告正文身份，尤其是机器不抽取文字的 PDF。机器不会识别图片文字，也不会自动判断截图真实。

教师 review 保存在提交包之外，由教师维护；学生不能以自填 review 代替验收。格式如下，示例中的占位值全部替换为实际值；`screenshots` 必须列出每张图，不能只保留示例这一项：

```json
{
  "reviewer": "实际复核教师姓名",
  "manifest_sha256": "当前 submission-manifest.json 的 SHA-256",
  "report_sha256": "已复核报告文件的 SHA-256",
  "report_student_id": "本人学号",
  "report_passed": true,
  "screenshots": [
    {
      "file": "evidence/x.png",
      "sha256": "这张截图文件的 SHA-256",
      "student_id": "画面中的学号",
      "experiment_id": "01",
      "run_id": "画面中且对应已提交 coursekit.run 的运行标识",
      "passed": true
    }
  ]
}
```

`file` 是清单中的包内相对路径，使用 `/`；`experiment_id` 为两位字符串。`sha256` 和 `report_sha256` 与清单相应文件项一致，`manifest_sha256` 绑定当前清单本身的哈希，可用 `(Get-FileHash -Algorithm SHA256 -LiteralPath <实际文件>).Hash.ToLowerInvariant()` 获取。哈希值只作一致性检查，不能用它替代打开报告和图片。`run_id` 必须与已提交的 `coursekit.run` 记录对应，且实验/项目号相同。缺项、重复项、多余项或用一项代替多张图都会失败；未复核或不合格不得填 `true`。

完成逐张复核并保存包外 review 后，教师执行：

```powershell
.\.venv\Scripts\python.exe -m coursekit submission-check --directory .\提交\实验01 --student-id $rosterStudentId --review .\教师复核\实验01-review.json
```

只有机器身份与文件检查通过、教师已复核所有截图且各项合格，才满足本章身份与提交证据验收前提；业务成果仍按本章评分表评定。无学号、`UNREGISTERED`、名册不一致、实验/项目号错误、run_id 无法对应、截图与原始结果不一致、缺图或未人工复核，均不能通过验收，须退回补证。补证应重新实际运行或重新取得合格截图，重新生成清单并复核；禁止补写或覆盖旧运行数据中的身份。

这是一项提交验收前提，不额外增加或扣除独立分值。各实验和项目评分总分仍为 100 分，基础路径与模型路径同分。预期失败若按契约发生、身份完整且恢复证据真实，可以获得对应分析分；技术结果失败与身份不合格是两种不同情况。
