# 《云计算与大数据处理》实验课程总体设计方案

面向计算机专业本科生。课程由八个实验和一个个人综合项目组成。

本方案参考 [AID](https://gitee.com/ryukinkou/AID) 的 Windows、CPU 与渐进实验编排，借鉴 [MSD](https://gitee.com/ryukinkou/MSD) 的真实运行证据、失败修复和个人交付规则。实际参考文件及转化过程见 [参考材料分析](research/reference-analysis.md)。技术取舍由 [官方证据与选型说明](research/technology-evidence.md) 支撑，核实日期为 2026-09-11；“前沿”不等于要求学生安装当日最新版本。

课程从 [课程导论](<../00. 课程导论与准备/课程导论.md>) 开始，再依次进入八个实验和个人综合项目。

## 1. 课程要培养的能力

完成课程后，学生应能解释并实现一个小型数据产品的完整路径：原始数据怎样被可靠接收，怎样证明清洗正确，何时值得并行，增量更新失败后怎样恢复，规则怎样变成可检索证据，服务怎样暴露统计与查询能力，最后怎样根据质量、权限、可靠性和资源证据决定能否发布。

课程面向计算机科班、无大数据开发经验且编码能力偏弱的本科生，不把 Python、SQL 的熟练程度当作未经确认的事实。教师可根据基础情况安排字典、函数、文件读写、`SELECT/WHERE/GROUP BY` 与主键复习。每章采用“小数据预测—运行脚手架—核对关键字段—补全关键局部逻辑—变式验证”，不要求学生从空白搭建整套平台。

### 1.1 可评价的课程目标

| 目标 | 完成课程后能够做什么 | 直接证据 |
|---|---|---|
| C1 数据与云接口 | 用对象键和清单管理输入，解释计算与存储职责，验证传输完整性 | 源文件与下载文件散列一致，能指出模拟服务与真实云的差别 |
| C2 大数据计算 | 建立数据契约、列式产物和分区处理，比较串行与进程执行 | 质量报告、Parquet、执行计划、Dask 与 DuckDB 结果对照 |
| C3 可靠增量更新 | 对重复、非法、晚到事件与中断给出明确策略 | 首次处理、重放、回滚、恢复的状态与结果证据 |
| C4 规则证据供给 | 为检索、摘录和可选生成提供可追溯、可过滤、可评价的数据 | 文档/索引版本、相关性标签、逐题证据、拒答案例 |
| C5 服务与治理 | 发布可调用接口并测试数据版本、权限、性能和失败行为 | HTTP 请求、延迟分位数、日志、缓存键、发布检查 |
| C6 独立工程判断 | 无论是否使用 AI 助手，都能证明关键决策正确 | 本人先行预测、核心规则修改 diff、失败分析、现场变式 |

### 1.2 AI 是应用背景和自愿实践，不是课程前提

AI 基础设施不只是模型文件和 GPU。训练需要去重、许可与切分正确的数据；检索需要最新且带来源的知识；推理需要可度量的请求与资源记录；Agent 需要受控工具返回结构化、可核验的数据。四类消费方式共享数据质量、权限、版本和可观测性要求。

本课直接实现的是使用日志分析、规则检索、证据查询和数据服务。实验 05、06 保留固定 BGE 与本地 Qwen 的完整实践，也保留无需模型的词法/摘录基础路径；两条路径同等满足必达目标。学生 AI 助手和系统模型均自愿，课程不安排训练基础模型，也不把八次实验改成提示词练习。

## 2. 统一案例与技术边界

统一案例为“模拟服务使用分析与规则查询平台”。课程脚本在学生本人的笔记本上生成合成服务记录与虚构规则；数据生成不调用真实模型，也不接入真实账号、个人日志、私人对话或付费调用账单。课程按每名学生仅使用本人笔记本设计，不把学校服务器、机房设备、共享算力、云账户或助教作为运行前提。

平台由本机 `coursekit seed` 生成三个模拟服务 `assistant/search/batch` 的使用记录和虚构规则。每条服务记录包含稳定 `event_id`、UTC 时间、服务、模型档位、输入输出 token、耗时和状态。默认输入为 20,000 条合法唯一记录、100 条完全重复记录、2 条非法记录，共 20,102 行。规则文档包含不同版本、公开/内部范围、撤回信息与一条不可信注入样例；问题集合预先区分开发集和最终验收集。

八个实验使用同一课程目录，`coursekit seed` 生成的记录和规则沿两条主线累积，并在服务与发布阶段汇合；学生保留基线，再做隔离的对照修改，每次提交保留身份信息、配置、版本与结果。

```mermaid
flowchart LR
  L[使用日志] --> A[01 可信接入] --> B[02 质量契约与分层]
  B --> C[03 批量计算与性能]
  B --> D[04 增量状态与恢复]
  R[规则文档] --> E[05 规则整理与检索] --> F[06 证据查询与评价]
  D --> G[07 数据服务与可观测性]
  F --> G
  A -.版本证据.-> H[08 治理与发布]
  B -.质量证据.-> H
  C -.性能证据.-> H
  D -.恢复证据.-> H
  E -.索引证据.-> H
  F -.评价证据.-> H
  G --> H --> I[个人综合项目]
```

实验 03 不直接把性能表交给实验 05。实验 05 的检索内容来自规则文档；当前实现只把实验 04 统计快照哈希纳入索引清单，作为跨主线版本标记。实验 04 的增量汇总与实验 06 的规则证据服务在实验 07 汇合；实验 08 汇总各层版本和验收证据。交叉虚线表示证据依赖，不冒充内容输入。

### 2.1 默认栈与诚实边界

| 层次 | 本课实际使用 | 学生能观察的机制 | 不能据此声称 |
|---|---|---|---|
| 对象存储接口 | 本机 Moto S3 HTTP + boto3 | bucket/key、endpoint、上传下载、内容散列 | 已部署公有云、已验证云耐久性或生产 IAM；临时 Moto 停止后不保留云侧状态 |
| 数据存储与分析 | JSONL、Parquet、DuckDB | 类型、去重、列式存储、分区、聚合、清单 | 已部署完整分布式湖仓或实现 Iceberg 全部事务 |
| 并行计算 | 单机 Dask LocalCluster，独立 worker 进程 | 调度、分区映射、聚合、序列化、并行开销 | 已验证跨机器网络或故障恢复；它是真进程执行，不是循环模拟 |
| 增量更新 | SQLite 主键、事务和检查点 | 重放幂等、提交前失败回滚、恢复、晚到处理 | 已部署 Kafka/Flink 流集群或获得所有外部系统的端到端 exactly-once |
| 规则检索基础路径 | 字符 TF-IDF/BM25 与权限、版本过滤 | 可复算表示、来源、排名、检索评价 | TF-IDF 是语义 embedding |
| 证据查询基础路径 | 引用原文的确定式摘录 | 检索、证据组装、拒答、引用检查、评价闭环 | 摘录等于调用 LLM；引用存在就等于完全忠实 |
| 自愿本地模型路径 | 固定 BGE；Qwen3.5 0.8B Q8_0 本地生成 | 真实 embedding、模型调用、语义/生成与基础路径对照 | 不运行就不能完成课程；模型回答流畅就可发布 |
| 服务与工具 | FastAPI/Uvicorn、本机 HTTP、固定统计查询 | 服务边界、缓存、请求负载、只读工具能力 | 已获得公网生产安全；请求中的 `role` 字段不是身份认证系统 |

实验 05 的本地模型路径为“词法基线 → 固定 BGE → 词法/语义对照”；实验 06 为“原文摘录 → 默认本地 Qwen → 引用与依据对照”。模型路径只在本人笔记本上使用固定制品和 CPU，属于选做的完整实践；基础路径无需模型，两条路径同等满足必达目标并可获得满分。选择基础路径的学生无需标 `SKIP` 或分析教师模型输出；选择模型路径者提交真实身份、调用与逐题证据。课程任务不依赖外部付费 API 或云端模型服务。

### 2.2 环境与费用

课程按每名学生使用本人笔记本运行设计，默认使用 CPU、本机回环地址和个人课程目录。Windows 11 64 位、Python 3.12、16 GB 是参考环境；物理 16 GB 笔记本的兼容性仍未验证，FF11 环境记录不得外推为该配置认证。基础路径无需 Docker、模型、GPU 或外部服务；Docker 保留为选做对照。模型路径使用固定 BGE 与 Qwen3.5 0.8B Q8_0 制品，在本机 CPU 运行，无法使用模型路径时仍可完成基础路径并取得同等评分。

固定模型与运行时的实际文件大小以制品清单为准，由教师记录核验；不将未验证的磁盘或内存预算写成学生通用设备门槛。基础路径和模型路径的个人实测范围分别记录，不相互外推。

## 3. 八次实验的递进矩阵

| 次序与实验主题 | 先修与读取产物 | 本次新增知识；累计能力 | 交接产物 | 必须本人完成；AI 允许辅助 |
|---|---|---|---|---|
| 01 对象存储接口与可复现环境 | Python/SQL 基础；无前次产物 | JSONL、HTTP 对象接口、环境隔离、散列、可复现输入；形成可信起点 | 原始事件/文档/题目、身份文件、传输校验记录 | 先解释对象键与本地路径、预测散列；AI 可协助环境报错和 SDK 语法 |
| 02 数据湖与质量契约 | 01 原始事件和散列 | 数据类型、非法值、主键、去重、列式存储、清单；形成可信分析数据 | `data/silver/events.parquet`、质量报告、silver 清单、每日服务汇总 | 先写去重键和质量规则，亲改一项规则；AI 可审查 SQL 与提出反例 |
| 03 分布式批处理与性能分析 | 02 合法 Parquet；01—02 版本和质量 | 进程 worker、任务图、分区、局部/全局聚合、开销；解释何时并行 | Dask/DuckDB 正确性对照、不同 workers/partitions 性能记录 | 手算局部聚合如何合并，改变分区做受控比较；AI 可解释任务调度日志 |
| 04 增量事件处理与故障恢复 | 02 数据契约；03 分批与计算代价 | 事件时间/处理顺序、主键幂等、检查点、事务；批转增量 | SQLite 状态、重放/失败/恢复证据、增量服务汇总 | 先推演重复和中断结果，修改晚到/批量策略；AI 可协助定位 SQL 错误 |
| 05 规则文档整理与可解释检索 | 01 文档；04 增量汇总用于版本血缘 | 版本、权限、词法检索；自愿完成 BGE 语义对照 | 索引/清单、Top-K 来源、过滤案例 | 小排名预测，补全一段排序或过滤逻辑；AI 助手可选 |
| 06 证据查询与结果评价 | 05 索引与文档 | 拒答、引用、Recall@k、dev/test；自愿完成 Qwen 生成对照 | 摘录/生成结果、冻结测试、失败题目 | 手算一个指标，补全证据选择逻辑；AI 助手可选 |
| 07 数据服务部署与可观测性 | 04 增量汇总、06 查询函数 | HTTP、结构化统计、版本化缓存、延迟/错误 | HTTP 负载、日志、统计接口 | 预测缓存影响，补全一项固定接口规则；AI 助手可选 |
| 08 数据治理与可信发布 | 01—07 全链路和证据 | 权限过滤、提示注入数据边界、撤回/失效、旧索引检查、发布门槛 | 发布检查、攻击/恢复案例、全链路交付包 | 本人解释一个越权/旧版本失败并做变式；AI 可审查遗漏项，不能生成虚假 PASS |

### 3.1 实验组织原则

每个实验围绕前序产物、本人预测、真实运行、核心规则修改、结果复核和证据整理展开。教师按学习目标组织活动；学生材料说明任务、必要操作、提交物与评分，不给任务分配固定时长，也不按课堂或课后切分必做内容。模型路径始终为选做，基础路径覆盖全部必达目标。

## 4. AI 使用规则与独立学习设计

AI 助手使用采用三层边界，并在每份手册用一句话重申；未使用者不必提交空白记录。

**可以辅助：** 解释库 API、定位环境错误、产生额外测试、审查代码、润色本人已经写下的结果。学生必须记录采用与拒绝的建议并运行验证。

**必须先本人做：** 主键和去重策略、质量规则、事务边界、微型结果预测、指标手算、相关性标签、性能因果解释。先保留自己的答案，再让 AI 提问或质疑。之后的修改要写清原因。

**不可代做或伪造：** AI 替代指定独立代码修改、现场验收、本人观察，或生成没发生的日志/截图/数字/参考资料。不得把 AI 输出直接变成最终测试集答案，或上传真实密钥与私人数据。

每章至少包含两项独立活动：一项先预测再运行；一项修改核心规则或代码并提交 diff。至少一次受控失败必须保留“失败条件—观测—解释—修复—复验”。禁止把“我运行了脚本，看到 PASS”作为完整报告。

报告模板见 [实验报告模板](../报告模板/实验报告模板.md) 与可选的 [AI 使用记录模板](../报告模板/AI使用记录模板.md)。身份码与截图只能关联提交者，不能单独证明原创，需结合代码改动和现场解释。

## 5. 评价设计

建议课程总评采用八次实验平均分 60% + 个人综合项目 40%。八次实验各按 100 分评分；05、06 的模型路径与基础路径使用同一“链路对照与证据分析”评分维度，模型不是额外加分捷径，也不是满分门槛。

八次实验共用评价方向：原理与先行预测、实际执行与数据正确性、独立改动、对照与失败恢复、报告证据。使用 AI 助手者另做简短披露，未使用者不交记录。性能结果没有更快、模型没有更准，都不自动扣分；实验控制正确、结果真实、解释合理才是关键。评分看受控证据与分析，不以模型大小或绝对性能替代。

项目按任务书单独给出 100 分细则，要求个人复用已学模块交付可运行 MVP、整体方案和验收数据，不要求搭建一套新的组件平台。项目材料见 [项目任务书](../09.%20个人综合项目/项目任务书.md) 与 [项目方案手册](../09.%20个人综合项目/项目方案手册.md)。

## 6. 教师如何保证这门课真正可开

旧版基础路径及固定 BGE + Qwen3.5 0.8B Q8_0 组合已有 FF11 实际环境记录；适用范围以教师指南和对应归档证据为准。本次更新了规则语料与问题文本，旧版模型指标不能作为新版语料的验收结果，新版模型路径仍需复验。物理 16 GB 笔记本的兼容性也尚未实测。学生默认路径为本人笔记本 CPU，基础路径与选做模型路径同等评分；不把额外 GPU、大模型或云资源作为课程拓展推荐。

逐项检查方法、设备边界、评分一致性与复核流程见 [教师实施与验收指南](教师实施与验收指南.md)。该指南区分课程功能与已有实测证据，不用技术文档的支持声明替代 Windows 实机结果。
