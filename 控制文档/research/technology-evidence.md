# 技术证据与选型说明

适用课程：《云计算与大数据处理》，计算机专业本科生，8 次实验 × 4 学时，另设两周个人综合项目。

核实日期：2026-09-11（America/Los_Angeles）。本文记录当日查阅的官方文档事实，不将文档中的 `latest`、`current` 或示例模型名称视为课程应采用的版本。正式开课应使用经过整套验收的课程锁定版本和离线包。

本文的“文档事实”来自下列官方主源；“教学建议”是基于学时、Windows 环境和学习目标作出的设计判断。文档存在不代表某一机器已经实测通过，资源预算也不是厂商性能保证。

## 一、选型结论

课程采用两条诚实汇合的主线：使用日志经可信接入和质量分层后分别进入批量分析与增量状态；规则文档经版本/权限整理后进入检索与证据查询。增量统计与规则查询在 HTTP 服务汇合，各层证据最后进入发布门禁。这里的“先进”指学生能处理数据版本、过期证据、检索错误、重放、资源竞争和不可重复评估问题，而不是安装最多的软件。

本课程冻结数据与服务主线为 Windows 原生 Python 3.12、Moto S3 HTTP 模拟服务、DuckDB/Parquet、Dask LocalCluster 真正多进程、SQLite 事务微批与 FastAPI。实验 05/06 提供两条同等完整路径：一种关键词排序与确定式原文摘录；固定 BGE 与 Qwen3.5 0.8B Q8_0 本地模型实践。学生自愿选择，未选择模型者不写 `SKIP`、不分析教师模型输出，仍可满分。Docker、Spark 和 Qdrant 不作为主线前提；更大模型与高级调参为选做。

完整课程不能被“纯聊天机器人”取代：至少前半程应考核模式、数据量、分区、聚合、执行计划和可靠更新；后半程以检索和生成应用验证这些数据工程决策产生的后果。

| E03 | [Amazon S3：服务与一致性模型](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html)。S3 对对象 PUT/DELETE 提供强读后写一致性；单一键的更新是原子的。 | 不应沿用“S3 一律最终一致”的旧讲法。单对象原子性不等于多个对象组成的数据集事务。教学 S3 服务只能验证所实现的接口，不能用本机测试推导公有云耐久性或 SLA。 |
| E04 | [Apache Iceberg：可靠性](https://iceberg.apache.org/docs/latest/reliability/)。表快照记录完整文件集合，提交以原子方式替换元数据路径；支持历史快照、回滚和乐观并发写。 | 主线可以用不可变数据文件与清单解释数据版本；必须写明简化清单不具有完整 Iceberg 事务保证。该页关于早期 S3 最终一致性的背景文字不能覆盖 E03 的现行一致性说明。 |
| E05 | [Apache Spark：Structured Streaming API](https://spark.apache.org/docs/latest/streaming/apis-on-dataframes-and-datasets.html)。不同 sink 的容错保证不同；`foreachBatch` 默认仅提供至少一次写入，可结合批次标识去重。控制台和内存 sink 主要用于调试。 | 检查点解决恢复位置问题，业务 `event_id` 解决重复事件问题，输出事务解决半次写入问题，三者须分别讲授。不能仅因“设置了 checkpoint”就声称整个系统 exactly-once。 |

| E07 | [Ollama：Windows](https://docs.ollama.com/windows)。提供 Windows 原生应用，支持 PowerShell 调用，本地 API 默认位于 `http://localhost:11434`；安装和模型存储均需要磁盘空间。 | 优先让 Windows 原生服务承担推理，不在无 GPU 学生机上额外增加 GPU 容器部署。模型下载、磁盘位置和本地端口必须课前验收。文档不保证所有模型在 16 GB 无 GPU 机器上可用或快速。 |
| E08 | [Ollama：生成 embedding](https://docs.ollama.com/api/embed)。`/api/embed` 接收模型名称和单条/多条文本，返回 embedding，并提供截断、维度等请求选项。 | 语料和查询使用同一模型、同一预处理规则；模型标识和维度写入索引清单。模型替换后重建索引。预先缓存真实 embedding 能减少课堂等待，但学生仍须完成至少一条现场编码与检索验证。 |
| E09 | [Ollama：生成响应](https://docs.ollama.com/api/generate)。接口支持流式响应、结构化输出、`keep_alive`，并返回输入/输出 token 数、加载耗时、生成耗时；耗时单位为纳秒。 | 区分冷启动、预填充、生成和 HTTP 总耗时。吞吐可计算为 `eval_count / (eval_duration / 1e9)`。缓存命中和缩短上下文应作为可测变量，而非仅展示漂亮回答。 |
| E10 | [MLflow：RAG 评估](https://mlflow.org/docs/latest/genai/eval-monitor/scorers/llm-judge/rag/)。将检索相关性、证据充分性与答案依据性区分为不同评价对象；其内置 RAG judges 依赖含检索 span 的 trace，充分性还需要预期事实。 | 主线先使用人工金标准和可复算检索指标。LLM judge 可作扩展，需报告模型和误判样例；不把有付费外部 judge 的示例当作完全离线免费基线。MLflow 平台本身不必强制安装。 |
| E11 | [Dask：Python 部署 API](https://docs.dask.org/en/stable/deploying-python.html)。`LocalCluster` 在本机创建 scheduler 与 workers；`processes=True` 使用进程；worker 内存限制是尽力而为。 | 比较 1/2 workers 与不同分区数，记录独立进程、调度开销和聚合结果。这里是真正多进程任务执行，但所有进程仍共享一台机器的硬件和故障域，不能声称完成多机高可用验证。 |
| E12 | [MinIO 官方社区仓库](https://github.com/minio/minio)。当日页面显示该仓库由维护者于 2026-04-25 归档，处于只读状态。 | 新课程不要写“拉取最新 MinIO 社区版即可”。如复用既有镜像，需注明锁定版本、来源、教师维护责任；更合适的是经当前验收的替代 S3 服务，或明确标为协议模拟器的本地教学实现。 |

## 三、AI 时代数据基础设施应教清的变化

以下是结合 E02—E11 作出的教学设计推断，不是某个厂商规定的唯一架构。

1. **数据同时服务统计和模型上下文。** 同一批事件既能计算服务耗时、失败率，也能更新知识库的有效版本；结构化记录与非结构化文档应通过稳定 ID、来源和时间相互关联。
2. **版本需要贯穿整个答案。** 一次答案应能回溯到数据快照、文档版本、chunk 规则、embedding 模型、检索参数和生成模型。只记录 Git commit 不够，因为数据和模型可在代码不变时变化。
3. **数据质量必须与用户错误关联。** 重复事件会把成本算高；过期文档会给出旧答案；跨版本重复 chunk 会占满 top-k；模式漂移可能把数值当字符串；只有检测结果没有影响分析，不算完成质量实验。
4. **新鲜度是数据管线的性质。** “加入新文档之后最终能检索”应测量端到端延迟；删除或撤回的数据不能仅从原文目录删除，还须追踪下游 chunk、索引和缓存。
5. **正确性需要失败场景证明。** 至少一次受控重复输入、一次处理中断、一次晚到数据、一次缺失证据请求，应贯穿后续实验复用。
6. **评估是发布输入。** 人工标注的检索金标准、拒答集合和固定负载应在调参前建立；调参集与最终验收集分离，防止把答案写死后报告满分。
7. **云成本是数据处理选择产生的结果。** 压缩、少读列、批量 embedding、索引增量更新、上下文长度、缓存、并发限制都能改变资源消耗。没有接入真实收费云服务时，用“模拟费率估算”标注结果，不能称为真实账单。

## 四、组件取舍与资源风险

| 对象 | 主线建议 | 风险与处理 |
|---|---|---|
| Python 环境 | 教师锁定一种受依赖支持的 Python 小版本；独立虚拟环境；直接调用虚拟环境解释器 | PowerShell 执行策略可能阻止激活脚本；不必要求全局放宽执行策略。将 `python` 路径和当前目录显示在验收结果中。 |
| DuckDB/Parquet | 承担列式分析、质量检查、版本产物 | 不要通过 `.fetchall()` 或转完整 pandas DataFrame 消除列式查询的优势。用小规模可手算数据做正确性，用固定较大规模数据做性能观察。 |
| 云对象存储 | Moto 模拟 S3 HTTP 接口，呈现 bucket/key/endpoint/凭证与计算存储分离 | 本地目录不是 S3。明确缺失多机耐久性、生产身份策略、网络故障模型；不把它称为完整云平台。 |
| Dask | 主线 LocalCluster 真正进程 workers，使用已有 Parquet 数据 | 本机多进程可测调度、序列化和并行开销；不是模拟循环。仍不能从单机推断跨机扩展或容灾。 |
| Spark | 同一 Parquet 产物上的可选扩展或一次集中实验 | Windows Java、驱动、镜像拉取和内存会占用课时。小数据上分布式可能更慢，这本身是应该解释的结果。 |
| 增量处理 | SQLite 事务微批、稳定事件 ID、持久化处理状态、可控故障注入 | 它用于理解重放和恢复，不是 Kafka/Flink 流集群。不能用一个永不重启的 `while True` 循环证明容错。迟到策略先用 6—10 条事件画时间线，再扩大数据量。 |
| 规则检索 | 基础路径任选一种关键词排序；模型路径使用固定 BGE，第二种词法方法与 RRF 为进阶 | 精确编号与数字约束仍需关键词或结构化过滤；余弦相似度不是答案可信度。模型路径保留完整索引和对照，但不是满分门槛。 |
| 证据查询 | 基础路径用确定式原文摘录；模型路径用默认 Qwen3.5 0.8B Q8_0，限定上下文和输出长度 | 两条路径均核验来源、拒答、权限和 dev/test。生成质量低不自动扣调用链分，但无依据内容不可通过发布门禁。 |
| 可观测性 | JSONL 结构化请求日志、CSV 指标汇总、每次实验 run_id | 最低要求应能定位慢在读取、检索还是生成，区分质量失败与 HTTP 失败。完整 OTel/MLflow 服务部署可以后续选做。 |

16 GB 内存是课程规划基线；磁盘预算按 [Windows 环境准备](../../docs/Windows环境准备.md) 和教师实际模型包大小确定，并为个人副本留余量。最终应在教师准备的 Windows 机器上按完整顺序冷启动验收，并保留环境、版本、峰值内存、耗时和模型下载大小记录；文档研究不能替代这些实测。

## 五、AI 使用边界建议

这部分属于课程评价设计：使用 AI 的边界必须以可观察的学习行为表达，不能仅写“合理使用”。

| 学习活动 | 建议规则 | 可提交证据 |
|---|---|---|
| 环境错误定位、API 用法解释、脚手架补全 | 允许 AI；必须验证返回的包名、参数和命令，并记录实际执行结果 | 提问摘要、采纳/拒绝项、报错与修复前后结果 |
| SQL/ETL 优化建议、额外测试样例生成 | 允许 AI 提案，学生负责正确性和反例 | 同一数据上的结果对照、执行计划、学生解释 |
| 主键与去重键、迟到策略、数据契约 | 先独立写出选择与理由，再允许 AI 质疑 | AI 使用前的短答案、修改理由、受控失败结果 |
| 小数据聚合、事件重放推演、余弦相似度/RRF、Recall@k 或 MRR | 至少一个案例禁止 AI 代算；要求学生手算并与程序核对 | 手算过程、程序结果、差异解释 |
| 金标准、测试集、依据性和引用核验 | 最终判断必须由学生完成；AI 不得自动生成后直接充当标准答案 | 文档 ID/原句位置、人工相关性标签、分歧说明 |
| 实验观察、失败分析、报告结论 | AI 可润色已经写出的事实，不能生成未发生的运行记录或代写观察 | 原始日志、run_id、结果文件、自己的因果说明 |
| 上机验收与口头解释 | 在指定短环节禁用 AI，解释一个关键决策并处理微小变式 | 现场预测、修改、运行和口述 |

使用 AI 助手者简短披露“在哪些步骤使用、采纳或拒绝了什么、如何核实”；没有使用者无需提交记录或空白声明。评分看结果可复现、概念理解和证据质量，不按 AI 使用次数奖励或惩罚。

## 六、发布前必须解决的现实问题

1. 依赖锁定不能只锁 Python 包：还需锁镜像 tag/digest、模型标识、模型缓存或下载清单、输入数据散列和课程代码版本。
2. 预发数据应包含来源、许可说明、数据字典、预置错误及固定随机种子。若为合成数据，明确标注，不把它称为真实生产流量。
3. 大陆校园网络对模型站点、镜像仓库的可达性应由教师提前确认；手册应给出离线材料校验方法，而不是临时搜索不明镜像。
4. 默认成功路径、失败注入路径和恢复路径应各自可重跑；覆盖数据应限制在本课程指定输出目录，给出重置前会影响的产物。
5. 学生评估集不能与实现中的硬编码答案同源。自动校验应检查不变量，例如重放前后唯一事件数不变、撤回文档不再被引用，而不只是匹配一份漂亮输出。
6. 教师应明确“4 学时”按本校每学时 45 或 50 分钟计；长下载和第一次模型加载不应挤占课堂原理、故障分析和独立验收时间。
