## 2. 本章问题、继承产物与知识积累

用自己的话写 100—200 字：本章解决哪个数据问题；前一个实验交给本章什么；本章给下一个实验什么。若读取的是原始文档而不是前章输出，应分别指出实际文件依赖和知识依赖。

| 输入文件/表/服务 | 来自哪次实验 | 使用哪些字段或版本 | 开始前如何确认可用 |
|---|---|---|---|
|  |  |  |  |

写清本章实现边界，例如“本次为 Moto S3 API 仿真”“本次为 Dask 单机多进程”“本次为 TF-IDF 词法向量”“本次为证据摘录”。不要把仿真、基线或本机实验写成尚未实现的生产能力。

## 3. 本人先行预测与核心概念

此部分必须先独立完成，再运行验证。允许预测错误，但不允许看到结果后伪装成事先预测。

1. 写出手册指定的输入小样本、规则和要预测的问题。
2. 展示计算/画图/事件时间线过程，说明分母、排序、边界或事务范围。
3. 记录预测结果与实际结果，分析差异。

| 问题 | 运行前预测 | 程序结果 | 差异原因与证据 |
|---|---|---|---|

## 5. 结果、对照与指标

先写必须成立的不变量，再写会波动的指标。不变量如唯一事件数、重放后总量、被撤回文档不出现；浮动指标如耗时、吞吐、检索分数。对照手册中的成功条件解释结果，性能数值以本人环境的实际测量为准。

| 对照项 | 基线配置 | 修改配置 | 保持不变的条件 | 结果与文件 |
|---|---|---|---|---|
|  |  |  |  |  |

每个指标写明计算方式。例如 Recall@k 的分母是该问题的相关文档数；延迟分位数来源于哪些请求；吞吐量的分子是成功请求还是全部请求；模拟成本与实际账单分开记录。

至少用一段话回答：为什么结果符合或不符合预测；哪些证据支持这个解释；还存在什么其他原因。不能仅写“效果较好”“速度明显提升”。

## 8. 结论、局限与交接

写出本章已经证明的 2—3 点，以及没有证明的至少一点。明确下一实验应读取的产物、版本和前置条件。示例：“已证明重复事件重放不增加 SQLite 表中的唯一事件；尚未验证多机网络故障；下章服务读取本次生成的增量统计文件。”示例只展示写法，不能当作自己的结果。
