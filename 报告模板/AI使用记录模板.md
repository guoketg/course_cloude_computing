# AI 使用记录模板

课程：《云计算与大数据处理》　实验/项目：________　姓名/学号：________。

本表用于说明 AI 对工作的实际贡献与本人验证责任，不要求学生必须使用 AI，也不按调用次数评分。只填写真实发生的记录。不要粘贴密钥、账号、未脱敏数据或无关私人聊天。

## 1. 使用前约定

本次允许 AI 辅助的活动：________。

本次必须先本人完成的预测、手算、核心实现或评估标签：________。

本次禁止 AI 代做的现场验收或独立环节：________。

若本次未使用 AI，写明“本次未使用 AI”，然后填写第 3 节的独立完成声明；第 2 节可省略。

## 2. 逐项记录

每个有实质影响的请求填写一条；连续多次修正同一个问题可以合并，但应保留关键变化。

| 字段 | 本人填写 |
|---|---|
| 时间、所在实验步骤 |  |
| 工具/模型，能确认的版本或日期 |  |
| 目的，例如解释 SDK 参数/分析错误 |  |
| 提示词摘要与提供的数据范围 |  |
| AI 建议摘要 |  |
| 本人采用的部分 |  |
| 本人拒绝/改写的部分与理由 |  |
| 本人实际修改的文件、函数或规则 |  |
| 验证命令与结果文件 |  |
| 对独立环节的影响：无/先本人完成后讨论 |  |
| 尚未验证或仍存疑的部分 |  |

以下是假想的填写示例，仅说明格式，不可当作自己的记录：

> 目的：解释“重放后请求数增加”。AI 建议忽略重复异常。我检查后认为仅忽略异常仍可能使检查点提前推进，因此没有直接采用；本人将事件写入与检查点更新保持在同一事务，并用“提交前中断—重启—重复投递”复验。具体是否需要这样修改，应以自己的代码与实际结果为准。

示例体现的是决策和验证，不是“AI 已确认正确”。如果 AI 建议合理且验证通过，直接说明即可，无需强行寻找错误。

## 3. 独立完成声明

我在使用 AI 之前独立完成了：________。

我亲自实现并能解释的核心改动是：________。

我亲自核对的评估标签、引用依据或数值口径是：________。

我确认提交的运行记录、截图、测量值和失败记录均来自本人的实际实验；AI 参与部分已按实披露。签名/日期：________。

## 4. 教师复核提示

教师可让学生对记录中的一项建议回答：它为何适用；修改哪一行会让保证失效；哪个输入能区分两种方案。不要用提交聊天长度或 AI 风格检测器代替理解验收。
