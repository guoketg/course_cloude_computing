## 1. 实验内容与目的

### 1.1 本次解决的问题

前四次实验已经能回答“平台处理了多少推理请求、消耗多少 token”。现在平台还要回答“资料能保存多久、学生每周有多少算力、谁能查看维护安排”。前一种答案来自结构化统计，后一种来自政策文档。把两类输入连到同一个系统，才构成可更新、可追踪的 AI 数据应用。

本次不训练大语言模型，也不把“关键词向量”叫作深度语义模型。先建立易检查的字符 TF-IDF 与 BM25 基线，再用真实 CPU 嵌入模型做对照，理解模型在数据平台中的位置。

你将完成以下任务：

6. 用哈希把文档、实验 04 统计快照与索引联系起来。

### 1.2 必须自己讲清楚的概念

| 概念 | 在本实验中的具体含义 | 容易发生的误解 |
|---|---|---|
| 文档版本 | 同一 doc_id 的政策修订号 | 把旧版与新版一起作为现行证据 |
| 文档切分 | 把正文分成保留来源和偏移的片段 | 只留下文本，无法定位原出处 |
| TF-IDF | 词项频次乘上逆文档频次 | 认为数值向量必然包含深度语义 |
| BM25 | 带词频饱和及长度归一化的词法打分 | 把分数当成概率 |
| 语义嵌入 | 训练好的神经网络计算稠密表示 | 认为语义检索必然优于所有词法题 |
| 混合检索 | 合并两种检索排序，本课用 RRF | 直接相加量纲不同的分数 |
| 数据血缘 | 记录某索引来自哪份资料和统计快照 | 只写一个“最新版”字符串 |

RRF 是 reciprocal rank fusion，即倒数排名融合。第一个排序器把某片段排在第 1 名，第二个排在第 3 名，则它的融合分为 `1/(60+1)+1/(60+3)`。这里的 60 是平滑常数，不是返回片段数。

## 5. 阶段三：切分与来源追踪

`chunk_documents()` 的默认窗口为 160 字符，重叠 32 字符，步长为 128。字符偏移采用左闭右开区间 `[start,end)`。`chunk_id` 形如 `quota@v2:0-75`，同时包含文档身份、版本与位置。

```python
for start in range(0, len(body), size - overlap):
    end = min(start + size, len(body))
    piece = body[start:end]
    if end == len(body):
        break
```

`min` 避免最后一个片段超出正文长度。最后的 `break` 避免生成只重复尾部的小片段。必须先验证 `0 <= overlap < size`，否则步长可能为零。

本课默认短政策均小于 160 字符，因而默认得到 13 个片段。这不说明真实长文档不需要切分，而是让你先检查来源对应关系，再在独立改动中主动制造跨片段边界。

```powershell
.\.venv\Scripts\python.exe -m coursekit lab05 --mode lexical
.\.venv\Scripts\python.exe -c "from coursekit.intelligence import load_index; i=load_index(); print('chunks=',len(i['chunks'])); print([(x['chunk_id'],x['start'],x['end']) for x in i['chunks'][:4]])"
```

这次命令真实建索引并写入文件。未修改语料时应为 `source_rows=16`、`active_documents=13`、`chunks=13`、`mode=lexical`。

输出的哈希不必与别人相同；不同统计快照或不同正文都会形成新版本。程序把 stats 快照哈希纳入版本，而不把统计结果塞进政策段落后让模型猜测。

## 6. 阶段四：从词项到混合检索

### 6.1 字符二元组

中文没有天然空格分词。`terms()` 把连续中文拆成相邻两个字符，如“算力配额”变为“算力、力配、配额”；英文数字串如 CPU、event_id 作为完整词项。这个规则无须词典，易复现，但不能自动理解“运算额度”和“算力配额”是近义表达。

```powershell
.\.venv\Scripts\python.exe -c "from coursekit.intelligence import terms; print(terms('算力配额 CPU event_id'))"
```

应能看到 `算力`、`力配`、`配额`、`cpu`、`event_id`。大小写归一化减少同一技术词被拆成多个维度的情况。

### 6.2 TF-IDF 与归一化

本课采用平滑 IDF：`idf(t)=log((1+N)/(1+df(t)))+1`。N 是片段总数，df 是出现该词项的片段数。大量文档共有的词获得较低区分权重，少见的词获得较高权重。

```python
matrix = term_counts * idf
matrix /= np.maximum(np.linalg.norm(matrix, axis=1, keepdims=True), 1e-12)
scores = matrix @ query
```

前两行让每个片段向量的长度为 1；查询也做相同归一化。此后点积等于余弦相似度。`1e-12` 避免零向量除零。这里是词法空间，不能因为出现“向量”二字就称其为神经嵌入。

### 6.3 BM25 与 RRF

BM25 为重复词项设置收益递减，同时比较文档长度和平均长度。源码中 `1.5` 是词频饱和系数，`0.75` 控制长度归一化强度。本实验理解其作用即可，不在 4 学时内推导概率检索完整理论。

RRF 使用各检索器的名次：

```python
scores = 1 / (60 + ranks(primary)) + 1 / (60 + ranks(bm25))
```

词法模式下 `primary` 是 TF-IDF 余弦；语义模式下它是神经嵌入余弦。即使某个无关文档的两个原始分数都是 0，RRF 仍会给它正数，因为它仍有名次。因此**不能用 RRF 是否大于 0 来判断证据足够**，下一实验会单独实现门控。

```powershell
.\.venv\Scripts\python.exe -c "from coursekit.intelligence import search; q='缓存键应包含哪些信息？'; [print(m,[(h['doc_id'],round(h['score'],5),round(h['lexical_cosine'],4)) for h in search(q,method=m)]) for m in ['tfidf','bm25','hybrid']]"
```

三个排序的首个命中应为 `cache`。默认该文档两次排名均第一，RRF 分应约为 `0.0327869`。这个数不是“3.28% 正确率”。逐项核对 `score`、`lexical_cosine`、`bm25_score` 的含义。

```powershell
'@ | .\.venv\Scripts\python.exe -
```

仅加一个空行也会改变字节级 SHA256，即使政策语义未变。这种保守策略容易审计，但可能带来不必要的重建；报告应区分“字节身份”和“语义等价”。预期先显示 `EXPECTED_FAILURE`，再显示 `version_changed=True`。

`TemporaryDirectory` 是 Python 管理的专属临时目录，退出时仅清理该目录。不要改成删除个人项目目录。

## 10. 常见问题与排查

| 现象 | 定位步骤与处理 |
|---|---|
| 提示缺少实验 04 汇总 | 检查当前位置与实验 04 是否完成，不能重新 seed 冒充前序成果 |
| Python 中文终端乱码 | 确认文件 UTF-8；必要时当前会话设置 `$env:PYTHONIOENCODING="utf-8"`；JSON 文件是主证据 |
| 片段数量不是 13 | 检查是否保留 48/12 改动、增加了政策或更改审核状态 |
| 旧索引拒绝服务 | 查看文件哈希及是否重跑实验 04，按依赖顺序重建索引 |
| RRF 有分数但没有相关内容 | 排名融合不是证据置信度，检查原始余弦与正文 |
| 公开检索出现内部片段 | 检查 `allowed` 是否在排序前构造，停止后续问答 |
| 模型下载慢 | 使用课前缓存，保存真实失败记录；不要多次并发下载 |
| semantic 缺少 sentence_transformers | 回到根目录 AI 依赖安装步骤，确保用项目解释器 |
| 更换模型后维度变化 | 正常，但必须重建索引，查询也必须使用同一模型 revision |
| 修改参数似乎无效 | 结束原进程，重新执行命令；默认函数参数在 import 时绑定 |
