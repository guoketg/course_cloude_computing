# 教师实施与验收指南

本指南面向任课教师与助教，用来把课程材料变成可实际开设的 8 次实验和两周个人项目。时间、先修、能力目标与总体评价见 [课程总体设计方案](../课程总体设计方案.md)，每章操作与评分以对应实验目录为准。

必须区分三种状态：`PASS` 表示指定路径实际执行且满足检查；`FAIL` 表示实际执行不满足；`SKIP` 表示未执行，并写原因。脚本导入成功、阅读官方文档、观看演示，都不能替代该路径在本人机器上的实际运行。

## 1. 开课前的最低准备

### 1.1 教学约定

- 课内为 8 × 180 分钟；下载安装、模型缓存与系统重启在课前完成。
- 学生已有 Python/SQL 基础；无 Docker/Linux/GPU 前提。标准平台为 Windows 11 64 位、Python 3.12、CPU、16 GB 内存。
- 统一使用虚构校园 AI 推理事件与自制政策材料；不接入真实个人日志。
- 每章先保留预测，再运行；至少一项本人核心规则/代码改动，必须有结果变化和 diff。
- 05/06 标准路径含真实 CPU embedding 与本地小 LLM 对照。TF-IDF 和摘录作为可复算第一阶段；更大模型、收费 API、真实云与高级调参才是选做。
- “让模型执行被测功能”属于实验本身；“用 AI 替代指定独立手算/实现/验收”属于学习辅助边界。两者应向学生分别说明。

### 1.2 课前问卷与预检

在第 1 次课前一周收集 Windows 版本、CPU、内存、可用磁盘、Python 是否可运行、学校网络是否可访问依赖站点。不得要求学生公开设备序列号、账户密码或 API 密钥。

先选择至少一台普通 CPU/16 GB 参考机完成全套；再抽查一台学生机。若学生机不满足标准环境，提前安排机房、校内共享推理服务或正式降级，避免到实验 5 才发现问题。资源限制登记设备能力和错误即可，不应使学生因无法购买硬件而失去学习机会。

### 1.3 依赖与模型冻结

使用课程包的 `requirements.lock.txt` 安装数据/词法基线；完整标准模型环境按 `requirements-models.lock.txt` 和实验 5/6 手册配置。直接依赖清单 `requirements.txt` 用于阅读，不应临时全部升级。安装后记录 `pip freeze`、课程代码版本、数据种子和散列。

Ollama 运行时与模型另行记录：运行时版本、模型名、模型包标识、实际下载大小与获取日期。语义模型记录名称及可确认 revision。不得仅记录“最新版”。课程默认小模型选择用于 CPU 教学，不宣称它是当日最强模型。

对模型缓存做断网或离线模式验证：能够从已有本地文件完成模型加载、文本编码与生成，才叫“可离线运行”。仅看到下载目录存在不够；有些加载代码仍会请求模型仓库元数据。若该版本仍需联网，必须提前修正加载路径或明确网络前提，不能在手册里写成离线。

## 2. 教师基线验收

以下命令仅供教师在自己的课程验收目录执行。示例安装位置为 `C:\BDP`，按实际位置修改。不要用学生正在提交的目录做重置或生成测试。

### 2.1 安装与检查

```powershell
Set-Location 'C:\BDP'
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip check
New-Item -ItemType Directory -Path '.\outputs' -Force | Out-Null
$teacherTestRoot = Join-Path (Get-Location) ('outputs\pytest-teacher-' + [guid]::NewGuid().ToString('N'))
.\.venv\Scripts\python.exe -m pytest tests -q --basetemp $teacherTestRoot
```

虚拟环境隔离课程依赖；`pip check` 检查依赖约束；测试验证代码中的关键不变量。测试通过并不意味着 HTTP 服务、模型、整套手册都已实测，需要继续下面各节。

如 PowerShell 允许本地脚本，运行：

```powershell
.\scripts\verify-environment.ps1
.\scripts\run-baseline.ps1
```

若学校执行策略禁止脚本，按脚本内的解释器命令逐条执行即可，不要求学生永久放宽全局执行策略。`verify-environment.ps1` 检查基础模块，不涵盖真实模型；`run-baseline.ps1` 是教师用的 01—06 词法/摘录基线 smoke，学生仍应逐章学习，不能用一键执行代替预测和改动。

基线脚本在 `outputs/smoke-...` 中创建独立数据根，避免覆盖课程主数据。记下脚本最后输出的真实路径，后续 HTTP 验收必须指向同一个根。不要猜测最近一个文件夹就一定是这次结果。

### 2.2 基线确定值与检查口径

| 项目 | 应检查什么 | 不应强求什么 |
|---|---|---|
| 默认数据 | 20,000 条合法唯一 + 100 重复 + 2 非法，共 20,102 行 | 不把手工修改后的数据还套用默认数字 |
| S3 仿真 | HTTP 上传/下载真正发生，内容散列一致 | 公有云耐久性、跨区域一致性 |
| 清洗 | 仅合法唯一数据进入 silver；质量报告解释剔除项 | 只看最后显示“成功” |
| 列式/批处理 | Parquet 可读，DuckDB 与 Dask 关键聚合一致 | Dask 必须比 DuckDB 快 |
| 进程 | 使用真正 worker 进程并保留配置/进程证据 | 单机等于跨机容灾 |
| 微批恢复 | 首次处理、重放、中断、恢复各有状态；检查点与事务一致 | 检查点本身提供所有外部输出的 exactly-once |
| 词法/摘录 | 模式如实写入结果；来源和拒答可查 | 把它们当成 embedding/LLM |
| 版本 | 清单与实际文件对应；旧索引/篡改被发现 | 只检查响应里存在 `version` 字段 |

数据行数与逻辑结果可严格核对；带时间戳的产物散列、性能时间和生成文本可能变化，分别记录可重现范围。

### 2.3 HTTP 服务与发布验收

打开两个 PowerShell 窗口，二者进入同一课程目录，并将 `BDP_ROOT` 设置为 **上一步实际输出的 smoke 根目录**。下方路径只是示意，必须替换 `smoke-实际编号`。

窗口 A：

```powershell
Set-Location 'C:\BDP'
$env:BDP_ROOT = 'C:\BDP\outputs\smoke-实际编号'
.\.venv\Scripts\python.exe -m uvicorn coursekit.service:app --host 127.0.0.1 --port 8000
```

窗口 B：

```powershell
Set-Location 'C:\BDP'
$env:BDP_ROOT = 'C:\BDP\outputs\smoke-实际编号'
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/health'
.\.venv\Scripts\python.exe -m coursekit lab07 --requests 20
.\.venv\Scripts\python.exe -m coursekit lab08
```

窗口 A 用 `Ctrl+C` 正常停止。验收结束后，在两个窗口中分别移除临时环境变量，避免后续误用：

```powershell
Remove-Item Env:BDP_ROOT -ErrorAction SilentlyContinue
```

不同数据根会使“我的文件已更新但服务仍旧”成为真实问题；教师应先核对环境变量与工作目录，再判断代码错误。发布检查还应配合人工检查源码，确认不是硬编码 PASS。权限、注入和数据篡改测试的覆盖范围应如实说明；一组测试不能证明全面安全。

当前发布门禁读取冻结的 `evaluation_test_extractive.json` 和真实 HTTP 负载证据，服务默认采用可复算摘录路径。门禁通过不等于真实 LLM 回答已经满足引用/忠实度要求；模型对照应独立分析。若个人项目把 LLM 作为实际发布生成器，应增加与该生成器一致的验收，不能借用摘录结果替其背书。

## 3. 真实模型标准路径的准备与验收

### 3.1 课前材料

准备三类材料：依赖安装包；真实语义模型；本地 LLM 运行时与模型。按学校允许的渠道分发，不绕过许可或任意采用不明镜像。模型许可、获取来源与校验值应随材料一起提供。

模型环境安装示例，在教师参考机和标准学生机课前完成：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-models.lock.txt
.\.venv\Scripts\python.exe -m pip check
ollama --version
ollama pull qwen3:0.6b
ollama list
```

`ollama pull` 会下载模型，必须安排在课前且确认磁盘足够；具体名称以实验 6 手册和当前课程配置一致为准。若学校更改模型，不仅改命令，还须更新配置、模型标识、演示证据和预期运行时间。

实际语义模型通过实验 5 的标准第二阶段建立索引并记录模型 revision。先用课程默认短语料完成 smoke，不要第一次就批量处理大量文档。模型依赖包含较大的 Python 包，教师要验证锁定文件适合 Windows/Python 3.12，而不是把其他操作系统的完整 freeze 直接分发。

### 3.2 实际对照命令

在已经完成实验 1—4、且已有数据的教师测试根中，先保留词法结果，再执行真实语义模式：

```powershell
.\.venv\Scripts\python.exe -m coursekit lab05 --mode lexical
Copy-Item -LiteralPath '.\outputs\lab05\retrieval.json' -Destination '.\outputs\lab05\retrieval_lexical_teacher.json'
.\.venv\Scripts\python.exe -m coursekit lab05 --mode semantic
Copy-Item -LiteralPath '.\outputs\lab05\retrieval.json' -Destination '.\outputs\lab05\retrieval_semantic_teacher.json'
.\.venv\Scripts\python.exe -m coursekit lab05 --mode lexical
```

以上 `Copy-Item` 相对路径适用于没有另设 `BDP_ROOT` 的课程主根；若使用隔离根，复制命令也要指向该实际根。复制用于保留两个模式，避免第二次运行覆盖第一份结果。索引文件也应按实验 5 手册保留必要清单。任一路径未实际成功，都不能继续称“完成对照”。最后一条恢复词法索引，与学生实验 05 的标准交接一致；后续实验 06 的摘录/真实 LLM 在同一词法检索输入上对照，实验 07 的轻量容器也消费这份词法索引。若另测语义索引的端到端路径，应单列该组数据版本与结果，重跑相应评价和 HTTP 验收。

生成阶段：

```powershell
.\.venv\Scripts\python.exe -m coursekit lab06 --split dev --generator extractive
.\.venv\Scripts\python.exe -m coursekit lab06 --split dev --generator ollama
```

确认 Ollama 服务真实收到请求，结果含模型与实际调用指标；抽查至少一个答案和引用。模型响应不是每次都相同，需保留逐题输出。设置相同随机参数也不应承诺所有软硬件下逐字一致。

调参只用 dev。配置冻结以后，再运行 test 并保留模式：

```powershell
.\.venv\Scripts\python.exe -m coursekit lab06 --split test --generator extractive
.\.venv\Scripts\python.exe -m coursekit lab06 --split test --generator ollama
```

标准课堂应让学生运行小模型对照，不要求把整个 test 集用大型模型执行。若参考机在预分配时间内无法完成，应在开课前减少生成问题数或缩短输出，并在教师验收配置中声明；不要课堂临时隐藏超时。

### 3.3 教师示范证据包

教师保存真实生成的输入、模式、模型标识、revision/包信息、硬件、命令、时间、逐题检索结果和生成结果。额外保留一个失败或劣于基线的例子，避免学生认为“更先进组件总能提高分数”。

示范至少展示：精确编号更适合词法的例子；改写/近义表达可能受益于语义的例子；相关性高但证据不足的例子；小模型引用存在但说法不被原文支持的例子。如果当前模型没有产生某类现象，不要伪造，改为提供经明确标注的人工反例用于讨论。

本轮开发验证曾实际观察到 Qwen3 0.6B 返回部分正确关键词，但不遵守指定 chunk 引用格式，使程序判定引用存在率为 0。它适合演示“关键事实覆盖”“格式契约”“证据忠实度”是不同指标。教师应读取本次实际保存的逐题报告，并保留原始版本；再次运行可能产生不同输出，不把这一观察写成模型永远失败的结论。

### 3.4 正式降级流程

遇到无法满足的硬件/网络/系统约束，先记录错误与已经采取的合理排查。教师安排机房或共享演示后仍无法让本人实跑时，采用下表记录：

| 字段 | 必填内容 |
|---|---|
| 未运行路径 | `lab05 semantic` / `lab06 ollama`，可分别标记 |
| 状态 | `SKIP`，不能写 `PASS` |
| 原因与排查 | 实际错误、硬件或网络约束；不要求私人账号信息 |
| 本人已运行部分 | 词法/摘录、数据管线、指标手算、独立修改等 |
| 教师真实证据 | 证据包版本、模型、运行日期、具体文件 |
| 本人分析任务 | 计算同一指标、解释差异、核验引用、预测参数变化 |
| 未获得的实测能力 | 明写没有在本人机器完成加载/调用/测量 |

教师按同等概念和分析深度评分，单独记录运行覆盖率，不要求学生购买硬件。SKIP 不自动豁免分析与独立修改；只运行基线而不完成指定分析，仍缺少相应学习证据。

## 4. 八次课的课堂组织

| 实验 | 教师课前复核 | 课堂重点提问 | 易误解点与纠正 |
|---|---|---|---|
| 01 | 环境、临时 HTTP 服务、散列 | 上传成功为什么还要比较散列？对象键是否等于文件夹？ | Moto 是 API 仿真，服务停止后云侧对象不作为持久源 |
| 02 | 默认异常数、Parquet、清单 | 同一个 event_id 内容不同应怎样处置？ | 简单去重规则要声明适用条件；Parquet 不是完整湖仓系统 |
| 03 | worker 进程、结果对照、配置保存 | 加一倍 worker 为什么可能变慢？ | 更慢可以正确；比较先检查结果一致 |
| 04 | 故障位置、事务与状态、晚到 | 数据写完但检查点没写会怎样？ | 主键、检查点、输出提交不是一个概念 |
| 05 | 真语义模型离线可用、词法/语义结果保留 | 为什么模型换了要重建索引？ | 字符向量不等于语义；相似度不等于可信度 |
| 06 | 真实小模型、dev/test、逐题证据 | 引用存在但说法错误怎么发现？ | 引用存在性和充分忠实度分开；LLM judge 不当唯一标准 |
| 07 | 两终端同根、实际负载、缓存版本 | 快了一半是缓存、少算了还是测量错了？ | 统计事件耗时与 HTTP 端到端耗时分开；role 输入非认证 |
| 08 | 真实篡改/版本/权限路径、恢复 | 为什么所有 HTTP 200 仍可能不准发布？ | 发布依据质量与权限等不变量，不只进程存活 |

每次保留 15 分钟整理与交接。助教先检查输入文件与配置，再看异常；不要直接替学生完成独立环节。可提供语法提示，但让学生自己决定规则并写下理由。

## 5. 评分的一致性与真实性

### 5.1 先看证据对应关系

报告里的每个重要结论应对应源数据、命令、版本、结果字段或代码 diff。截图可帮助定位身份，不能单独代替机器可读结果。学生输入被修改后，默认 20,000 等数字不再是唯一正确答案，应按学生契约计算。

模型分数、性能和延迟不要按高低排名评分。学生能证明受控比较、发现失败、解释局限，应得到相应分数。若数字非常漂亮但没有原始样本，应补查，不能因截图美观就默认真实。

### 5.2 独立环节抽查

每次随机抽一个微小变式，如修改 1 条重复记录、调低阈值、增加一个相关文档、把角色换为 public。先让学生预测，再运行。此环节不用 AI，可查阅自己的代码。记录理解情况，不靠 AI 风格检测器判断作者身份。

AI 记录检查“建议—采纳/拒绝—本人修改—验证”是否闭环。学生没有使用 AI 也可满分；大量调用不会增加分数。发现伪造证据时遵循学校正式流程，不在本指南自行制定处分。

### 5.3 两周项目的管理

第 2 天看一页用户问题与数据流；第 4 天看一次真实完整请求；第 7 天看两项核心改动和小数据参照；第 10 天看失败恢复；第 13 天看复建。教师每次只反馈阻塞主线的少数问题，避免把一个人两周项目膨胀成团队平台工程。

项目代码可复用课程组件，但应有两项关联独立改动。不要按新增组件数量、代码行数或模型参数量评价项目。详细 100 分表和失败上限见项目任务书。

## 6. 常见现场问题处理

| 现象 | 首先确认 | 处理方向 |
|---|---|---|
| 找不到模块 | 当前目录、`.venv` 解释器、pip 是否同环境 | 用完整解释器路径安装/运行，不要求全局安装 |
| PowerShell 脚本受限 | 学校策略、是否仅激活脚本受限 | 直接调用 `.venv\Scripts\python.exe`，不永久改全局策略 |
| 中文请求乱码 | 文件编码、请求 Content-Type、请求体字节 | 按手册显式 UTF-8；保留原始错误再复验 |
| Dask 子进程报错 | 从模块入口启动、是否有主入口保护、数据路径 | 避免在交互式片段中重复创建进程；先运行 1 worker |
| HTTP 端口占用 | 是否已启动同一服务、另一窗口是否仍运行 | 正常停止本人服务；不杀不明进程 |
| 明明更新却读到旧结果 | BDP_ROOT、当前目录、服务进程、索引清单、缓存键 | 依次核对路径和版本，不能只重启掩盖根因 |
| 模型缓存仍联网 | 是否请求仓库元数据、加载路径是否本地、revision 是否匹配 | 完成离线预检或登记网络前提；必要时正式降级 |
| 模型生成很慢 | CPU、上下文、输出上限、冷启动、并发负载 | 使用已验收小模型和短输出，分开冷/热测量 |
| 发布检查失败 | 哪项规则、实际文件是否修改、恢复是否完整 | 修复原因并重跑，不手改 release JSON 为 PASS |
