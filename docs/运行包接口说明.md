# 运行包接口与产物约定

供教师维护与项目扩展使用。正式学生操作以八份实验手册为准，所有命令在课程根目录运行。代码的共享路径由 `coursekit/common.py` 定义，默认指向根目录；设置 `BDP_ROOT` 可创建隔离的教学数据空间，不改变代码目录。

## 数据接口

原始事件位于 `data/raw/events.jsonl`，每行包含 `event_id/event_time/service/model/input_tokens/output_tokens/latency_ms/status`。时间使用带UTC偏移的ISO8601字符串，计数及延时是非负整数；`event_id`是事实身份，内容不同的同ID记录不能静默去重。默认生成20,000个合法唯一事实、100条完全重复、2条非法数据。

文档位于 `data/raw/documents.jsonl`，包含 `doc_id/title/text/version/visibility/updated_at/status`。先选每个doc_id的最大version，再按审核/撤回状态过滤；public/internal用于课堂角色模拟。问题位于 `questions.jsonl`，包含qid、question、相关文档ID、answerable、split、关键词与role。

## 命令与产物

以下统一省略前面的 `.\.venv\Scripts\python.exe -m coursekit`。

| 子命令 | 主要输入 | 主要产物/约束 |
|---|---|---|
| `identity --student-id 20260001 --lab 01 --stage start` | 本人学号 | student.json；身份标识仅用于证据关联 |
| `seed --rows 20000` | 固定种子42 | raw事件、文档、评价题及raw清单；不覆盖不同事件文件 |
| `lab01` | 原始事件 | outputs/lab01/storage.json；真实HTTP的Moto S3往返；临时服务退出即销毁内存对象 |
| `lab01 --endpoint http://127.0.0.1:5000` | 已启动的本机Moto服务 | 同一收据格式；不使用真实云凭据 |
| `lab02` | raw和lab01收据 | silver/events.parquet、gold/service_daily.parquet、质量报告/隔离记录/silver清单 |
| `lab03 --workers 2 --partitions 8` | Silver与清单 | benchmark-w2-p8.json及最近结果；Dask真进程、显式shuffle、SQL对照 |
| `lab04` | Silver及同版本lab03结果 | 每次生成data/state/runs/运行ID/events.sqlite；latest.json指针；实时汇总与重放报告 |
| `lab05 --mode lexical` | 文档与lab04实时汇总 | knowledge.json及manifest、retrieval_lexical.json；TF-IDF/BM25/RRF |
| `lab05 --mode semantic` | 同上、CPU模型 | 稠密向量与固定模型revision、retrieval_semantic.json；替换当前索引 |
| `lab06 --split dev --generator extractive` | 当前索引及dev题 | evaluation_dev_extractive.json；摘录不是LLM |
| `lab06 --split test --generator ollama` | 当前索引、test题、本机模型服务 | 逐题生成、真实token/时间/digest；不静默回退 |
| `lab07 --requests 20` | 已运行HTTP服务 | load_test.json；客户端顺序请求、错误、分位数和缓存；不代表最大吞吐 |
| `lab08` | 当前索引、SQLite、评价与HTTP证据 | release_checks.json；7项实际检查，失败后保留原因并非零退出 |

运行HTTP服务的独立命令是 `.\.venv\Scripts\python.exe -m uvicorn coursekit.service:app --host 127.0.0.1 --port 8000`。GET `/health`验证索引版本，GET `/stats`返回实验04汇总，POST `/ask`接收question与教学role，GET `/metrics`返回本进程指标。默认生成器是extractive；发布门禁不替LLM质量背书。

## 版本与运行顺序

实验02检查原始文件是否仍与实验01收据一致；实验03检查Silver哈希；实验04检查实验03数据版本；实验05把原始知识文件与实时统计快照哈希都放入索引身份；服务在查缓存之前核验这些哈希。实验08核验当前索引对应的测试与服务结果。

完成语义对照后恢复共同词法索引，再生成实验06正式基线和实验07结果。改变原始数据、清洗规则、文档、统计快照或索引参数后，要按依赖关系重跑下游，不能只修改manifest绕过错误。每个带模式/配置的结果独立保存；方便入口文件会更新为最新结果，对照前按手册另存。

`data/state/latest.json`保存运行ID、该次SQLite绝对路径和源Silver哈希。它用于当前工作区内恢复，不是可跨机器直接搬用的路径配置。分发学生项目时应按README重建数据，或将迁移逻辑作为本人明确实现的功能。

## 发布与测试工具

`requirements.lock.txt`是Windows基础依赖；`requirements-models.lock.txt`包含标准模型依赖；`requirements.container.txt`供可选Linux容器。`scripts/prepare_embedding.py`准备独立本地BGE目录；`scripts/run-baseline.ps1`创建隔离数据根完成01—06基础链路；`tests`检查少量关键性质。

`scripts/audit_docs.py`与`check-powershell.ps1`检查文档链接和PowerShell语法。`capture_validation.py`保存教师实际结果，`package_course.py`仅打包白名单目录，排除环境、模型、学生数据和教师完成版练习。所有验证覆盖范围见[运行验证记录](运行验证记录.md)。
