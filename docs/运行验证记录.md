## 3. 保留的反例与解释

### 并行计算并未自动变快

本次20,000行数据上，单 Worker 主计算约0.744秒，双 Worker约1.115秒；结果相同。Dask启动、任务与交换成本明显，且 service 键存在倾斜。该结果支持讨论“小数据为什么可能适合单机查询”，不能推广为所有 Dask 工作负载都更慢。一次测量也不是严谨性能基准。

### 小模型回答没有达到引用要求

Qwen3 0.6B 在词法检索输入下，开发集已回答9题中的引用存在性通过 **0/9**，关键词覆盖均值约0.778；测试集为 **2/9**，关键词覆盖均值约0.889。很多答案包含正确数字，却未附合法 chunk 引用，或只保留部分条件。原始逐题回答已保留，不改写成“全部成功”。

引用存在性、关键词覆盖和拒答判定都不是人工忠实度评分。三类负例主要由检索权限与规则层拒绝，不能把成功归因于小模型自行识别全部风险。小型合成数据集的检索高分不能推广到真实校园知识。

本次发布检查仅针对默认 **extractive 摘录服务**，不代表小模型生成质量合格，更不代表生产安全认证。学生若选用小模型作为最终服务，须另行制定并验证生成模式的发布条件。

### 离线缓存曾暴露真实缺陷

首次离线复验发现 Hugging Face SDK 要求未下载的另一套权重文件，尽管必要 safetensors 已缓存。已修正离线下载过滤与缓存路径，随后在 `HF_HUB_OFFLINE=1` 下成功运行。这个问题说明“曾经联网成功”不等于“断网后一定能用”。教师仍需验证实际分发的缓存或本地目录。

另已执行 `scripts/prepare_embedding.py`，把权重复制为普通模型目录；设置 `BDP_EMBED_MODEL` 为该目录、`HF_HUB_OFFLINE=1` 后实际建索引和查询，首位文档为quota，详见[本地模型目录验证](validation-evidence/local-model-probe-result.json)。

## 4. 模型身份与资源证据

- BGE：`BAAI/bge-small-zh-v1.5`；revision `7999e1d3359715c523056ef9478215996d62a620`；CPU推理。
- Ollama服务：0.31.1；当前命令行客户端0.32.13。接口实际调用成功，学校应统一版本并重新预检。
- Qwen模型：`qwen3:0.6b`，每条实际调用结果记录完整 `model_digest` 与 token/耗时字段。
- `ollama ps` 在CPU验证后显示 `100% CPU`、`781 MB`、context 2048。这是该次运行时观察，不是所有机器的固定内存保证，也不包括 Windows 与其他程序。
- `inference` 中的 Ollama耗时字段以纳秒为单位；`elapsed_seconds` 是客户端秒数。两者不能混用。服务器生成速率可用 `eval_count / (eval_duration / 1e9)`，没有实际 token 数据时不得从汉字数冒算。

## 6. 教师复验入口

按 [Windows环境准备](Windows环境准备.md) 创建干净环境，按01→08顺序运行。每次数据、依赖或模型版本变化后，保留旧证据，重新生成对应的下游索引、评价和服务记录。`scripts/run-baseline.ps1` 可在独立数据根复验01—06基础链路，但不包含个人改动、模型对照及07的双终端操作，不能用它替代完整教学验收。

`scripts/capture_validation.py` 只从真实输出复制教师证据，`scripts/package_course.py` 按白名单打包源码、文档、练习和这些小型证据文件，排除模型、环境、原始大数据和个人工作目录。
